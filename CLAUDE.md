# SalonOS

Multi-tenant SaaS for hair/beauty salons (Parlak Mediatech). Full
architecture — tenant isolation model, RBAC design, RLS strategy, phase
plan — was approved before implementation started; see the architecture
report shared with the project owner, and `README.md` here for the
condensed version. Don't re-derive these decisions from scratch; they were
deliberate and already argued through.

## Non-negotiables carried across every phase

- **Tenant isolation is RLS, not app-layer filtering.** Every tenant-owned
  table gets `tenant_id` + RLS policies from the migration that creates it,
  not "added later." Never trust a client-supplied `tenant_id` or
  `tenantSlug` for authorization — always re-derive from the session
  server-side.
- **Permission checks use permission keys, never role name strings.**
  No `if (role === 'SALON_OWNER')` anywhere in application logic — that
  quietly breaks the custom-role goal. Check permissions via the shared
  `has_permission()` mechanism (Faz 1+) instead.
- **`SUPABASE_SERVICE_ROLE_KEY`** is only read in `lib/supabase/admin.ts`,
  which is guarded by a `server-only` import — don't work around that by
  importing it elsewhere.
- **Money is `numeric`, never `float`/`double`. Timestamps are `timestamptz`
  (UTC), never naive local time.**
- **Financial records are append-only** — corrections are reversal rows,
  never in-place edits or deletes.
- Scope stays inside the currently-approved phase. Faz 0 is foundation only
  (no business tables/modules); Faz 1 adds multi-tenant + auth + RLS + RBAC
  - super-admin foundation. Don't pull Faz 2+ work (appointments, CRM,
    finance, inventory, color formulas, marketing) forward without an
    explicit go-ahead.

## Stack specifics that aren't obvious from training data

- **Next.js 16**: Middleware is `proxy.ts` (function named `proxy`), not
  `middleware.ts`. `params`/`searchParams` are always async. Typed
  `PageProps<'/route/[param]'>` / `LayoutProps<...>` helpers are globally
  available (generated by `next typegen`, which `next dev`/`next build`
  run automatically). Read `node_modules/next/dist/docs/` for anything
  version-specific before assuming an older API shape.
- **shadcn/ui uses the "base-nova" preset, i.e. Base UI primitives, not
  Radix.** Compose components with the `render` prop
  (`<Button render={<Link href="/x" />}>text</Button>`), not `asChild`.
- **Tailwind v4**: no `tailwind.config.ts`. Theme tokens live in
  `app/globals.css` (`@theme inline`, `:root`, `.dark`). The palette there
  is deliberate (warm neutral + muted teal `--primary`) — don't reset it to
  shadcn's default zinc/gray on a future `shadcn add`.
- **next-intl**: `localePrefix: "never"` in `lib/i18n/routing.ts` — URLs
  never show `/tr/`, but the `app/[locale]/...` routing is real. Use
  `lib/i18n/navigation.ts`'s `Link`/`redirect`, not raw `next/navigation`,
  inside the `[locale]` tree.
- Package manager is **pnpm**. `pnpm dlx` has a broken cache on the
  original dev machine (ENOENT on postinstall) — one-off CLI tools
  (`create-next-app`, `shadcn`, `supabase`) were run via `npx` instead;
  regular `pnpm add`/`pnpm install` work fine. If `pnpm dlx` fails again,
  fall back to `npx`.
